`grafana/provisioning/dashboards/dashboard.yml`

`/var/lib/grafana/dashboards`

File:

`grafana/dashboards/racepulse-control-room.json`

## 6. Dashboard Panels

The final dashboard contains the following sections.

### KPI Summary

Four summary cards provide a quick control-room overview:

1. **KPI Results**
   - Current KPI result count
   - Local demo: 9

2. **Critical Alerts**
   - Number of critical alerts
   - Local demo: 3

3. **Warning Alerts**
   - Number of warning alerts
   - Local demo: 3

4. **Latest Lap**
   - Latest lap number available
   - Local demo: Lap 3

---

### Lap Pace Delta by Car

This visualization compares pace deterioration across cars.

The metric is derived from the KPI results:

`delta_ms`

A higher delta indicates a larger difference from the car's best recorded lap.

---

### Gap Trend by Car

This visualization tracks how the gap to the leader changes across laps.

Relevant fields:

- `lap_number`
- `gap_to_leader_ms`
- `trend_ms_per_lap`
- `car_id`

This allows the dashboard to distinguish between cars whose gap is increasing, decreasing, or remaining stable.

---

### Alert Severity Distribution

This panel summarizes alerts by severity.

Local demonstration data contains:

- Critical: 3
- Warning: 3

The dashboard uses the `alerts` table and groups records by `severity`.

---

### Recent Alerts

The recent-alert panel provides an operational view of alerts generated by the analytical pipeline.

Displayed information includes:

- Time
- Car
- Alert signal / KPI ID
- Severity
- Message
- Delta

The local demonstration contains six alerts:

- 3 `SYS-STALE` critical alerts
- 3 `KPI-001` warning alerts

The repeated appearance of a car in this table is expected when the same car generates different alert types. They represent separate alert events rather than duplicate records.

---

### Current Car Status

The Current Car Status table provides one latest record for each car.

It displays:

- Car
- Latest lap
- Lap time
- Best lap
- Pace delta
- Pace status
- Gap to leader
- Gap trend
- Gap status

The latest KPI result is selected using the maximum database record ID for each car.

This prevents multiple historical rows for the same car from appearing in the current-status view.

## 7. Database Tables Used

The Grafana dashboard consumes analytical outputs from three primary MySQL tables.

### `kpi_results`

Used for:

- Lap time
- Best lap calculation
- Pace delta
- Pace severity
- Latest lap

Important fields include:

- `car_id`
- `lap_number`
- `lap_time_ms`
- `delta_ms`
- `severity`
- `event_time`

Best lap is stored directly as the `best_lap_time_ms` column (not derived from `lap_time_ms - delta_ms`, which gives a stale value on the exact lap a new personal best is set - see racepulse-control-room.json's Current Car Status query for the corrected version).

---

### `gap_trend_results`

Used for:

- Gap to leader
- Gap trend
- Gap severity

Important fields include:

- `car_id`
- `lap_number`
- `gap_to_leader_ms`
- `trend_ms_per_lap`
- `severity`
- `event_time`

---

### `alerts`

Used for:

- Alert count
- Alert severity distribution
- Recent alerts
- Alert messages

Important fields include:

- `kpi_id`
- `car_id`
- `severity`
- `message`
- `delta_ms`
- `event_time`
- `created_at`

---

## 8. SQL Logic

The dashboard uses SQL queries directly inside the Grafana dashboard configuration.

Examples of analytical operations include:

### Alert aggregation

Alerts are grouped by severity to produce the alert distribution.

### Recent alerts

Recent alerts are filtered using the alert creation timestamp and ordered from newest to oldest.

### Current car status

The latest KPI result for every car is identified using:

`MAX(id)`

The corresponding gap-trend record is then joined using:

- `car_id`
- `lap_number`

This creates a single current-state row per car.
